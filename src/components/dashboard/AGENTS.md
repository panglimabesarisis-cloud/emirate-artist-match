# Private agent presentation
- Your AI Agent uses AI Elements for messages, tool status, conversation and composer; server-generated report data feeds tables/charts and persisted action records supply confirmation controls, so model text cannot authorize side effects.
- Contract libraries share the reference card shell; contract-list visibility is a user-scoped local preference, while deletion uses existing protected booking RPCs so financial and accepted-contract rules stay authoritative.
- Contract previews paginate React-rendered content into measured A4 sheets; oversized paragraphs split without discarding text, and screen fitting scales the sheets rather than changing their print geometry or stored terms.
- Agent and account reference presentation uses scoped agent-account.css; settings, prompt entitlements, identity status and payout confirmation retain existing data/auth paths so HTML demo behavior cannot change security or credit rules.
- Artist monitoring shares live Inbox conversations; only an owner-confirmed transactional operator claim unlocks manual replies, and protected handback checks AI settings and credits.
- Conversation WhatsApp sends reserve notification rows before dispatch and reconcile delivery callbacks; ambiguous sends are never blindly retried.
- SupportWorkspace shares ticket/message rows across artist and admin views; append-only sender-verified messages preserve the thread while legacy reply fields retain client compatibility.
- ArtistOwnPrompts persists owner-only instructions separately from protected library content; limits are transaction-checked and prompts join the server instructions below safety rules.
- Registration ends in SignupPlanGate around the owner dashboard: the talent picks a plan, and a paid choice keeps it locked behind an invoice and hosted checkout link until effective_artist_plan is paid. The choice is auth metadata `signup_plan` because it only gates the screen (limits stay database-enforced); accounts without it are never gated.
- A pending talent who finished registration, paid the deposit and holds a paid subscription is approved server-side (approvePaidArtist, after subscription sync); rejected and suspended stay. The Subscribe badge derives from today's paid subscription, never from the admin-editable artists.plan, and needs no identity verification.
- Booking chats open full screen in ChatShell (components/chat/shell) for both sides: /chat/$id has no site header and sends the owning artist to /dashboard/chat/$id, where the composer stays locked until Take Over and AI Take Over locks it again. Settings pages derive invoice state from service_invoices and never infer it for chat-only invoices. Expiry follows src/lib/unpaid-expiry.ts (the expire_unpaid_records rule): expired bills leave the settings pages, show no pay button and are refused by invoiceCheckout; only the client side gets pay buttons and payment links. Client commission is tiered (drizzle 0087, client_commission_tiers, edited in master admin): the database alone computes a client's tier, rate and minimum withdrawal. The chat says its link was sent only after a chat_link WhatsApp notification was accepted. Every chat invoice is the dashboard's InvoicePaper in fixed A4 (InvoiceSheet), fed by src/lib/chat-invoice.ts, with the browser-built invoice-pdf download; a message without a saved invoice row shows no payment status.
- New talent, bookings, chats, portal requests and open jobs need a WhatsApp number proven by one-time code (drizzle 0088, phone-otp.server); the server and the artists trigger enforce it, accounts from before keep access, and site_settings `whatsapp_otp.required` (publicly readable) is the admin off switch.
- Artist rates are private (drizzle 0089): public pages, search, the site assistant and MCP search carry no artist price; rates reach clients only through the booking chat and invoices. rate_cards are readable by the team and admins, and anon has column grants on artists that exclude prices, so grant any new public column to anon explicitly.
- The artist overview shows a rate card reminder (RatecardReminder) only for a deposit-paid, submitted profile with no rate cards; it opens /join, which sets the starting price too.
- Ratecard dashboard, signup and admin share item fields and price validation; item prices cover stated scope, base totals exclude add-ons, database triggers retain legacy writes, and public/private agents read the same saved rules.
- Support tickets reuse the Inbox layout (inbox.css), and Inbox, Support and Your AI Agent share one chat backdrop in chat-fields.css.
- Team page access uses the shared checklist and database page gates; cross-page labels and document fields use narrow page-authorized RPCs instead of granting booking or quote tables.
