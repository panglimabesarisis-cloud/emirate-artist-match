# Private agent presentation
- Your AI Agent uses AI Elements for messages, tool status, conversation and composer; server-generated report data feeds tables/charts and persisted action records supply confirmation controls, so model text cannot authorize side effects.
- Contract libraries share the reference card shell; contract-list visibility is a user-scoped local preference, while deletion uses existing protected booking RPCs so financial and accepted-contract rules stay authoritative.
- Contract previews paginate React-rendered content into measured A4 sheets; oversized paragraphs split without discarding text, and screen fitting scales the sheets rather than changing their print geometry or stored terms.
- Agent and account reference presentation uses scoped agent-account.css; settings, prompt entitlements, identity status and payout confirmation retain existing data/auth paths so HTML demo behavior cannot change security or credit rules.
- Artist monitoring shares live Inbox conversations; only an owner-confirmed transactional operator claim unlocks manual replies, and protected handback checks AI settings and credits.
- Conversation WhatsApp sends reserve notification rows before dispatch and reconcile delivery callbacks; ambiguous sends are never blindly retried.
- SupportWorkspace shares ticket/message rows across artist and admin views; append-only sender-verified messages preserve the thread while legacy reply fields retain client compatibility.
- ArtistOwnPrompts persists owner-only instructions separately from protected library content; limits are transaction-checked and prompts join the server instructions below safety rules.
- Ratecard dashboard, signup and admin share item fields and price validation; item prices cover stated scope, base totals exclude add-ons, database triggers retain legacy writes, and public/private agents read the same saved rules.
- Support tickets reuse the Inbox layout (inbox.css), and Inbox, Support and Your AI Agent share one chat backdrop in chat-fields.css.
- Team page access is one list in src/lib/team-access.ts used by the invite checklist, roles and member workspace; the checklist hides tabs, while per-page database access still needs a schema change on Lovable.
